# 高血压出院随访助手（Hypertension Follow-up Agent）
> 面向高血压出院患者的随访智能体 Demo：出院后自动生成随访计划与到期提醒，患者通过与Agent对话完成随访并提取结构化信息，Agent 生成带来源的报告草稿，由医生审核确认后发布给患者。
---

## 1. 项目目标

做一个**随访智能体系统**。

核心功能：

1. **计划与提醒**：医生登记患者出院、生成随访计划，到期自动提醒患者和医生。
2. **患者端**：患者查看自己的随访任务和"我的随访信息"，与 Agent 对话完成随访，Agent 从对话中提取结构化信息，经患者确认后入库。
3. **报告草稿**：Agent 基于跟患者的对话、知识库检索结果，整理随访报告草稿，并标注参考来源，供医生审核。
4. **医生审核**：医生查看草稿，填写审核意见。
5. **结果发布**：患者能查看自己相关的随访记录，任务状态与处理结果保存到数据库。


## 2. 核心流程

```
出院记录 ──► 生成随访计划 ──► 到期提醒（站内通知）
                                   │
                                   ▼
                 患者查看任务 ──► 与 Agent 对话
                                   │
                    提取结构化字段（血压、症状、服药情况等）
                                   │
                          患者确认后写入随访记录
                                   │
                  规则风险分层（含红旗症状规则兜底）
                                   │
         ┌─────────────────────────┴───────────────────────┐
         ▼                                                 ▼
 Agent 生成报告草稿（待审核）                    高风险：给出120和医生电话，立即升级给医生
         │                                                 │
         └─────────────────────────┬───────────────────────┘
                                   ▼
                           医生审核，填写审核意见
                                   │
                                   ▼
                          患者查看最终报告，更新任务状态
```

## 3. 角色与权限

| 角色 | 可以做                                            | 不可以做 |
|---|------------------------------------------------|---|
| 患者 | 查看自己的任务、出院信息；与 Agent 对话；确认提取结果；查看已发布的报告；查看医生信息 | 查看他人数据；查看未审核的草稿 |
| 医生 | 查看名下患者的任务与记录；审核报告草稿；处理升级告警                     | 查看非名下患者的数据 |


## 4. 功能设计

### 4.1 随访计划与提醒
- 医生端给登记患者出院，给出诊断、医嘱、用药等信息。根据出院记录生成随访任务（如出院后第 1 周、第 2 周、第 4 周等）。
- 患者端生成站内通知、查看任务、完成任务。

### 4.2 患者对话与结构化提取
- 多轮对话，流式输出，工具调用状态不可见，Agent问问题要亲民、日常化，少用专业名词，转化成专业名词需要Agent做。
- 从对话中提取并校验字段：收缩压、舒张压、测量时间、症状、是否按时服药、漏服原因、不良反应。
- 提取完结果展示给患者确认，确认后入库，交给医生审核。

### 4.3 风险分层与红旗规则
- 风险等级由**规则**计算（血压阈值、是否出现胸痛/剧烈头痛/言语不清等红旗症状）。
- 命中红旗规则时，直接提示患者及时就医并通知医生。

### 4.4 报告草稿与知识库检索（RAG）
- 草稿由Agent生成，参考Agent与患者的交流，输出结构化 JSON：摘要、风险等级、异常点、建议、引用来源。
- 患者确认提交草稿后交给医生审核。
- 知识库支持 TXT / PDF / DOCX，文本切分、向量化、本地持久化，文件指纹检测变更并增量更新。

### 4.5 医生审核
- 待审核列表、查看、修改Agent生成草稿，填写审核意见发布给患者。

## 5. 状态机

**随访任务**

```
待随访 → 进行中 → 已提交 → 审核中 → 已完成
```

**报告**

```
草稿 → 待审核 → 已审核 → 已发布给患者

```

## 6. 技术架构

```
Streamlit（患者端 / 医生端）
        │  HTTP（携带登录凭证）
        ▼
FastAPI（鉴权、业务接口、状态流转）
        │
        ├── Agent（LangGraph / LangChain，ReAct + 工具调用）
        │      ├── 工具：查任务 / 查出院信息 / 查血压记录 / 提交随访记录 / 检索知识库 / 查病人信息 / 查医生信息 / 查随访记录
        │      ├── 大模型：（阿里云百炼接口）
        │      ├── 向量模型：（阿里云百炼接口）
        │
        ├── 关系型数据库（用户、医患、出院、任务、报告、通知）
        ├── 向量库（Chroma，本地持久化）
        └── 定时任务（APScheduler，到期提醒）
```

| 层 | 选型 |
|---|---|
| 前端 | Streamlit |
| 后端 | FastAPI |
| Agent | LangChain、LangGraph |
| 大模型 | （阿里云百炼） |
| 向量检索 | Chroma |
| 数据库 | 关系型数据库（含外键与状态约束） |
| 定时任务 | APScheduler |



## 本地启动

在项目根目录使用 Python 3.11 安装依赖。

```powershell
pip install -r requirements.txt
```

百炼密钥保存在环境变量 `DASHSCOPE_API_KEY` 中。模型名称和百炼服务地址位于 `config/rag.yml`。
项目根目录，激活虚拟环境，分别在两个终端运行以下命令。

```powershell
fastapi dev backend.py
```

```powershell
streamlit run app.py
```

## 体验一次完整随访

1. 注册医生并登记联系号码，再注册患者，选择这位医生为主管医生。患者可在侧栏「我的资料」更新自己的电话和既往病史。
2. 医生登录后在总对话输入“帮我登记患者出院”，核对预填卡并确认。系统安排出院后第 7、14、30 天的随访，北京时间上午 9 点开放。登记八天前的出院日期可以体验已到期的首轮任务。
3. 患者在「助手能做什么」选择「查我的随访计划」，从任务卡进入专属对话，填写或修改后确认提交。已保存的聊天与资料可在再次登录后继续查看。
4. 医生在聊天首页查看风险提醒和待审事项，在任务对话里核对原始记录与引用，选择通过、修改后通过或退回补充。审核通过后点击发布，患者可在总对话查询已发布报告。
